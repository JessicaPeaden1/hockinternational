Build ALL of the following n8n nodes in a single workflow JSON:

3. PHASE ROUTER TOOL (Code Node as tool)
   - Name: phase_router
   - Input: { currentPhase, userMessage, intent }
   - Logic:
       * Reads current phase state from session memory
       * Returns: { allowedActions, nextStepLabel, phaseGateRequired, errorIfSkip }
       * If intent tries to advance past a phase gate without approval:
         return { error: "Phase gate not cleared. User must confirm YES before advancing." }
       * Phase order is strictly: INITIATION → TEXTBOOK → MCQ → SLIDES → SCRIPT → FLASHCARDS → CLOSEOUT
       * No skipping phases under any condition
   - Returns structured JSON only

4. MONDAY.COM TOOL (HTTP Request Node as tool)
   - Name: monday_tool
   - Credential: "Monday.com API"
   - Board: "HOCK International Content Production"
   - Trigger: ONLY called AFTER user confirms YES — never auto-triggered
   - Actions supported:
       updateStatus    — update "Content Status" column on item
       addComment      — add formatted comment to item
       setDueDate      — set due date on item
       createSubtask   — create subtask under parent item
       uploadFile      — attach a file to a Monday.com file column (see section 4a below)
   - Status values (exact strings):
       "In Progress"                    — set when a phase begins
       "Textbook is Ready for Review"   — set after Phase 1 Dropbox upload confirmed
       "MCQs Ready for Review"          — set after Phase 2 Dropbox upload confirmed
       "Slides Ready for Review"        — set after Phase 3 approval
       "Slide Script Ready for Review"  — set after Phase 4 approval
       "Complete"                       — set at Phase 6 close-out
   - Item lookup: search by Study Unit ID in item name or custom column "Study Unit ID"
   - Subtask name pattern: "{studyUnitId} — {phaseName} — {YYYY-MM-DD}"
   - Comment format:
       "Phase {N} complete. {contentType} saved to Dropbox at {dropboxPath}. Date: {date}."
   - Required input fields: itemId (from session state), action, statusValue

4a. MONDAY.COM FILE UPLOAD (Execute Workflow Node — Sub-Workflow)
   - Sub-workflow file: monday-file-upload-subworkflow.json
   - Purpose: Attach a file (Excel, PDF, DOCX, PPTX) to a Monday.com file column.
     Monday.com requires a separate multipart/form-data POST to https://api.monday.com/v2/file
     using the add_file_to_column GraphQL mutation. This CANNOT be done with a simple
     column value update — it requires a dedicated Execute Workflow node in n8n.

   - How it works (3 steps inside sub-workflow):
       1. Call Dropbox /2/files/get_temporary_link to get a one-time download URL
       2. Download the file binary from that URL
       3. POST multipart/form-data to https://api.monday.com/v2/file with:
            query  = mutation ($file: File!) { add_file_to_column(item_id: ITEM_ID, column_id: "COLUMN_ID", file: $file) { id } }
            variables[file] = <binary file data>

   - Sub-workflow input fields (all required):
       itemId            — Monday.com item ID (integer, from session state mondayItemId)
       dropboxPath       — Full Dropbox path, e.g. /HOCK/CMA/SU5-2796/mcqs/CMA_SU5_2796_5a_MCQ_Final.xlsx
       fileName          — File name with extension, e.g. CMA_SU5_2796_5a_MCQ_Final.xlsx
       mondayColumnId    — Monday.com column ID for the file column (see column ID table below)
       mondayApiToken    — From "Monday.com API" credential (api_token field)
       dropboxAccessToken — From "Dropbox OAuth2" credential (access_token field)

   - Monday.com file column IDs (configure by opening Monday board → column settings → get ID):
       Textbook File column      → mondayColumnId: "files"        (CONFIRM in board — may differ)
       MCQs File column          → mondayColumnId: "files_1"      (CONFIRM in board — may differ)
       Presentation File column  → mondayColumnId: "files_2"      (CONFIRM in board — may differ)
       Slide Script column       → mondayColumnId: "files_3"      (CONFIRM in board — may differ)
     NOTE: Column IDs above are placeholders. To find actual IDs: in Monday.com open the board,
     click the three-dot menu on the column header → "Column settings" → the ID is shown, OR
     run: query { boards(ids: [18398486903]) { columns { id title type } } } against the API.

   - When to call this (phase mapping):
       Phase 1 close-out → upload textbook (.docx/.pdf) to Textbook File column
       Phase 2 close-out → upload MCQ Excel (.xlsx) to MCQs File column
       Phase 3 close-out → upload slides (.pptx) to Presentation File column
       Phase 4 close-out → upload script (.docx/.md) to Slide Script column

   - Calling sequence within a phase gate (example for Phase 2 / MCQs):
       1. User confirms YES to "update Monday task"
       2. Call monday_tool (updateStatus) → sets status, assignee, dates, description
       3. Call monday_file_upload sub-workflow → attaches .xlsx to MCQs File column
       4. Report both results back to user: "Monday task updated AND file attached."

   - Error handling:
       - If Dropbox path not found: report error, ask user to confirm path
       - If Monday column ID wrong: report error with instructions to look up correct ID
       - If token expired: report credential refresh needed
